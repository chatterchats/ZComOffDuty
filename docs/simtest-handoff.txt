## What's being tested
Off Duty adds operator fatigue tiers:
- Tired: −5% hit.
- Exhausted: −10% hit, −5% max HP, 5% chance per turn to lose 1 AP.
- Spent: −15% hit, −10% max HP, −5% movement, 10% chance per turn to lose 1 AP.
We compare squad outcomes against a baseline with no tier.

Conditions are `baseline`, `tired`, `exhausted` and `spent`. There are also two diagnostic ones,
`tier_effect_only` and `accuracy_only`, which aren't needed now.

## Hard rules

5. Commits, if asked: author `chatterchats <57570001+chatterchats@users.noreply.github.com>`. Never commit

6. Only one harness may run at a time. It talks to the game through one `cmd.txt`/`reply.txt` pair.

## Procedure
1. The human confirms the game is at the main menu.
2. Load the sandbox baseline campaign:
   python3 -I tools/simtest.py send "campaign load baseline" --timeout 300
   python3 -I tools/simtest.py send "wait phase=hub settled=1 timeout=240000" --timeout 260
   Both should print `ok | ...`.
3. Run the batch (5 runs × 4 conditions, interleaved; about 1 hour, ~2-3 min per run):
   python3 -I -u tools/simtest.py run --mission SK_Mapuzo_015 --enemies SS_Separatist_Threat_01 \
     --squad "Jacira Ako,Kabb Uppercut,Luco Bronc,Jae Mordant" \
     --conditions baseline,tired,exhausted,spent --runs 5 --turn-cap 25 --poll 3 --speed 4 \
     --keep 10 --no-reinforcements --free-first-slot --neutralise > dist/simtest/batchN.out 2>&1
   Use a new N each time so you don't overwrite earlier output (batch4 is taken).
4. Watch `dist/simtest/batchN.out`. Each run prints `run i/5 | <condition> ...`, a `setup:` line, then
   its result dict.
5. When it finishes:
   python3 -I tools/simtest.py report dist/simtest/<batch 4+ results>.csv ...
   Results are in `dist/simtest/*-results.csv` and transcripts in `dist/simtest/*-run.log`.

## What the flags do
- `--keep 10`: kills enemies by actor name until 10 remain, strongest first (B1s are kept last).
  10 is the agreed size: 11 was too much for Exhausted/Spent; 9 was too easy.
- `--no-reinforcements`: at setup, calls the game's `StopAllReinforcementWaves` on every encounter actor
  (found through the mission actor's `OrderedEncounterArray`). No more mid-mission kills. Any enemy that
  still shows up is counted in `arrivals`, not removed.
- `--free-first-slot`: REQUIRED. The game's player controller possesses the first squad member, which then
  has no AI controller, so the AI almost never acts with that unit (this is why Tesh, Cly and Jacira all
  "did nothing" in slot 1). The harness gives the player controller a hidden `BP_PreviewActor` pawn and
  has the unit's own `AIC_Planner` possess it again. Verified by the human watching: Jacira acted every round.
- `--neutralise`: sets Off Duty's fatigue gain to 0 (and AP loss on) so the harness controls the tier.
  It writes `src/OffDuty/MXM/values.lua` and backs up the original to `values.lua.simtest-backup`.
- Each run starts and ends with `ai off` and `speed 1`. `ai on` would otherwise persist across missions.
  The AI gets the squad once per run, right after setup, and keeps it for the whole mission.

## Expected noise (not a problem)

  10 s - the plans that never ended were cancelled" about once per squad turn with `--free-first-slot`.
  It costs ~10 s per round and nothing else. Only report it if a turn stalls repeatedly without
  finishing, or the run times out.
- Round 1 is taken over mid-turn (setup has to happen on the player's turn first); later rounds are
  planned by the AI from the start.
- `foes_left` can read 1 on a win (the last enemy's death lands after the read). Trust `result`, which
  comes from the mission's `MissionStatus`.

## Stopping a batch safely
Kill the python process by PID (don't `pkill -f` a pattern that also matches your own shell command):
  pgrep -f "tools/simtest.py run"   then   kill <pid>
Then put the game back and restore settings:
  python3 -I tools/simtest.py send "ai off"; python3 -I tools/simtest.py send "speed 1"
  python3 -I tools/simtest.py restore-settings

## Sandbox gotchas
- Replies are cut at about 900 characters.
- Under Proton every write looks like a file replacement, so the harness rewrites `cmd.txt` with one
  command per write. Don't hand-edit `cmd.txt` while a run is going.
- Enemy e-numbers renumber after each kill; the harness kills by actor name for this reason.
- `ai off` takes effect from the next player turn; `ai on` during a player turn takes that turn over.
- The squad health total excludes downed operators. Operators downed at any point are counted from Off
  Duty's `Squad | <name> downed/revived` log lines.
- Generic targets for get/set/call: `@pc` (player controller), `@world`, `@last`, or a full object path.
  Mission actors live under `/Game/Game/Maps/Skirmish/<map>/<map>_Root.<map>_Root:PersistentLevel.<name>`.

## Sanity checks on every run (flag any run that fails these)
- `first_slot` reads `freed Char_...` and `vanished` is empty. Anything else (`fell ...`, `pc pawn ...`, `no planner ...`, `possess failed`)
  means slot 1 was idle: exclude the run and report it.
- `waves_stopped` >= 1 and `arrivals` == 0. Arrivals mean reinforcements got through: report them.
- `foes_start` == 10.
- `health_start`: baseline/tired should match (291 with this squad); exhausted ~5% lower, spent ~10%
  lower (the max HP penalty). A mismatch means the tier wasn't applied.
- `ap_losses`: 0 for baseline and tired; occasional for exhausted (5%/turn/operator) and spent (10%).
  Losses in baseline/tired, or none at all across 5 spent runs, is suspicious: report it.
- `result` is win/loss/turn cap. `error: ...` or `timeout` rows: report them with the transcript lines.
